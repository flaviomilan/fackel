## 🎯 Objective

**Fackel** (German for *Torch*) is an **autonomous OSINT and security intelligence agent** designed to analyze a given domain and transform fragmented public data into **actionable security insights**.

Instead of merely enumerating assets, Fackel **correlates evidence, formulates hypotheses, and produces explainable risk assessments**, helping engineers, security teams, and decision-makers understand *what actually matters*.

---

## 🧠 Core Philosophy

Fackel is built around four principles:

1. **Intelligence over Enumeration** — raw OSINT data is useless without context.
2. **Explainability by Default** — every finding must be justified and reproducible.
3. **Ethical & Scoped by Design** — prioritizes passive intelligence and explicit consent.
4. **Agent‑Driven Analysis** — the agent decides *what to do next*, not a static pipeline.

---

## ✨ Key Features

### 🔥 Autonomous Agent

* Task planning and execution using a LangChain-based agent
* Dynamic decision-making based on intermediate results
* Hypothesis → Evidence → Confidence reasoning loop

### 🧭 Passive OSINT Collection (Default)

* WHOIS, DNS, CT Logs, search engines, professional networks
* Infrastructure intelligence via Shodan and Censys
* Zero direct interaction with the target

### ⚡ Active Scanning (Opt‑In)

* Optional Nmap-based service and port scanning
* Explicit `--active-scan` flag required
* Designed for authorized environments only

### 🧩 Correlation & Normalization

* Unifies heterogeneous data into a structured internal model
* Correlates signals across tools to reduce noise
* Identifies shadow IT, forgotten environments, and misconfigurations

### 📊 Risk‑Oriented Output

* Severity scoring by category (DNS, Infra, Email, TLS, Exposure)
* Human‑readable explanations for each finding
* Executive and technical summaries generated by the agent

## 🏗️ Agent Architecture

```
Objective (domain)
        │
        ▼
 Planner / Reasoner (LLM)
        │
        ├─► Tool Selection
        │       ├─ Passive OSINT
        │       └─ Active Scan (optional)
        │
        ├─► Evidence Normalization
        │
        ├─► Correlation & Hypothesis Testing
        │
        └─► Final Intelligence Report
```

The agent operates iteratively, reassessing its plan after each tool execution.

## 🧰 Available Tools

### Passive (Default)

* **whois_lookup** — Domain registration metadata
* **virustotal_subdomain_enum** — Subdomains via VirusTotal
* **dnsdumpster_lookup** — DNS records & infrastructure mapping
* **shodan_lookup** — Exposed services and banners
* **censys_lookup** — Hosts, certificates, and infrastructure
* **duckduckgo_lookup** — Generic OSINT web search
* **serp_search** — Advanced Google queries via SerpApi
* **extract_webpage_content** — Text extraction and analysis
* **search_linkedin_for_employees** — Public employee discovery
* **analyze_professional_profile** — Role and technology inference
* **job_search** — Tech stack inference via job postings
* **analyze_email** — Breach exposure checks

### Active (Requires `--active-scan`)

* **nmap_port_scan** — Service and version detection (`-sV -T4`)

## 🚀 Installation

```bash
git clone https://github.com/flaviomilan/fackel.git
cd fackel

# Instale as dependências e gere o ambiente isolado (Python 3.12)
uv sync --python 3.12
```

Execução direta pelo uv (não precisa ativar venv):

```bash
uv run fackel --help
```

## 📁 Estrutura (src/)

```
src/
├── cli/                # Typer CLI (`fackel` entrypoint)
├── fackel/
│   ├── agents/         # LangGraph agent loop (planner/run/normalize)

│   ├── reporting/      # Scoring e renderização
│   └── schemas/        # Tipos de estado do agente

├── tools/              # Ferramentas OSINT passivas/ativas
└── ...
```

sudo apt-get update && sudo apt-get install nmap

## ⚡ Usage

### Passive Intelligence Only (Default)

```bash
uv run fackel example.com
```

### Passive + Active Scan (Authorized Targets Only)

```bash
uv run fackel example.com --active-scan
```

### Saídas Estruturadas

- O agente gera relatório em Markdown/HTML (opção `--output`).
- Sempre é salvo um JSON estruturado com hosts, serviços, CVEs e evidências para correlação posterior (mesmo nome do HTML, com extensão `.json`, ou `<dominio>_report.json`).
