## 🎯 Objective

**Fackel** (German for *Torch*) is an **autonomous OSINT and security intelligence agent** designed to analyze a given domain and transform fragmented public data into **actionable security insights**.

Instead of merely enumerating assets, Fackel **correlates evidence, formulates hypotheses, and produces explainable risk assessments**, helping engineers, security teams, and decision-makers understand *what actually matters*.

---

## 🧠 Core Philosophy

Fackel is built around four principles:

1. **Intelligence over Enumeration** — raw OSINT data is useless without context.
2. **Explainability by Default** — every finding must be justified and reproducible.
3. **Ethical & Scoped by Design** — prioritizes passive intelligence and explicit consent.
4. **Agent‑Driven Analysis** — the agent decides *what to do next*, not a static pipeline.

---

## ✨ Key Features

### 🔥 Autonomous Agent

* Task planning and execution using a LangChain-based agent
* Dynamic decision-making based on intermediate results
* Hypothesis → Evidence → Confidence reasoning loop

### 🧭 Passive OSINT Collection (Default)

* WHOIS, DNS, CT Logs, search engines, professional networks
* Infrastructure intelligence via Shodan and Censys
* Zero direct interaction with the target

### ⚡ Active Scanning (Opt‑In)

* **Advanced Nmap** — Port scanning + service version detection + OS fingerprinting + vulnerability scanning
  * Service version detection (`--version-intensity 7`)
  * OS fingerprinting with `-O --osscan-guess` (requires root)
  * NSE vulnerability scripts (vulners, vuln category)
  * CPE (Common Platform Enumeration) detection
  * Structured output: ports, services, OS, hostnames, addresses, vulnerabilities, statistics
  * See [docs/advanced_nmap.md](docs/advanced_nmap.md) for details
* **Nuclei** — CVE/exploit template scanning (10,000+ templates)
* **Naabu** — Fast port discovery
* Explicit `--active-scan` flag required
* Designed for authorized environments only

### 🧩 Correlation & Normalization

* Unifies heterogeneous data into a structured internal model
* Correlates signals across tools to reduce noise
* Identifies shadow IT, forgotten environments, and misconfigurations

### 📊 Risk‑Oriented Output

* Severity scoring by category (DNS, Infra, Email, TLS, Exposure)
* Human‑readable explanations for each finding
* Executive and technical summaries generated by the agent

### 🎯 Adaptive Tool Selection

* YAML-based playbook system for tech-specific tool recommendations
* Semantic matching via OpenAI embeddings to detect technologies (GraphQL, WordPress, AWS, etc.)
* Redis-cached embeddings reduce API costs and latency
* Policy-driven execution adapts to discovered infrastructure

### 🌊 Streaming API

* FastAPI server with Server-Sent Events (SSE) for real-time analysis
* Incremental progress updates (step_update, partial_report, policy_decision, final_report)
* Integrates with front-end dashboards and CI/CD pipelines

### 🔍 Query System (RAG)

* **Natural language Q&A** over scan results: "Quais vulnerabilidades críticas existem?"
* **Semantic search** with OpenAI embeddings for relevant scan retrieval
* **LLM-powered answers** with sources and confidence scores
* **Automatic persistence** to MongoDB with complete scan history
* See [QUERY_QUICKSTART.md](QUERY_QUICKSTART.md) and [docs/query_system.md](docs/query_system.md)

## 🏗️ Agent Architecture

```
Objective (domain)
        │
        ▼
 Planner / Reasoner (LLM)
        │
        ├─► Tool Selection (Base Plan)
        │       ├─ Passive OSINT
        │       └─ Active Scan (optional)
        │
        ├─► Tool Execution
        │       │
        │       ├─► Policy Engine
        │       │    ├─ Playbook Matching (Vector Store)
        │       │    ├─ Redis-Cached Embeddings
        │       │    └─ Adaptive Tool Recommendations
        │       │
        │       └─► Evidence Normalization
        │
        ├─► Incremental Analysis (LLM)
        │       └─ Streaming Events (SSE)
        │
        ├─► Correlation & Hypothesis Testing
        │
        └─► Final Intelligence Report
```

The agent operates iteratively, reassessing its plan after each tool execution based on discovered technologies and infrastructure patterns.

### Extensibilidade / edição pro

- Registro de ferramentas extensível via `register_tool(name, fn, category="passive"|"active")` (pode ser chamado por plugins ou edição pro antes de instanciar o agente).
- Para novas dependências de API, use `register_tool_requirements(tool_name, ["ENV1", "ENV2"])`; para ferramentas offline/local, `register_always_on(tool_name)`.
- O `ToolRegistry` compartilhado é obtido com `get_tool_registry()` e fornece `plan()` para sugerir a ordem de execução considerando `active_scan` e capabilities.
- Planner LLM opcional: inicialize `LangGraphAgent(use_llm_planner=True, planner_model="gpt-4o-mini")` com `langchain-openai` instalado e `OPENAI_API_KEY` no ambiente. Se indisponível, o agente recai para o plano determinístico.

## 🗄️ Redis Cache (Optional)

Fackel uses **Redis** to cache OpenAI embeddings used in the adaptive policy engine. This eliminates redundant API calls, reducing costs and latency.

### Setup Redis

**Option 1: Use Langfuse's Redis** (recommended if you already have Langfuse running):

```env
# .env
REDIS_HOST=localhost
REDIS_PORT=6379
REDIS_DB=1  # Langfuse uses DB 0, Fackel uses DB 1
REDIS_PASSWORD=myredissecret  # From docker-compose.yml REDIS_AUTH
```

**Option 2: Dedicated Redis for Fackel**:

```bash
docker-compose -f docker-compose.redis.yml up -d
```

```env
# .env
REDIS_HOST=localhost
REDIS_PORT=6379
REDIS_DB=0
# REDIS_PASSWORD=  # No password in docker-compose.redis.yml
```

### Cache Management

```bash
# View cache statistics
uv run python manage_cache.py stats

# Clear all cached embeddings
uv run python manage_cache.py clear

# Test cache operations
uv run python manage_cache.py test
```

**Graceful Fallback**: If Redis is unavailable, the system automatically falls back to uncached embedding generation.

For more details, see [docs/embedding_cache.md](docs/embedding_cache.md).

```bash
docker-compose up -d langfuse
```

2. Acesse o painel em http://localhost:3000, crie o projeto e copie PUBLIC_KEY/SECRET_KEY.

3. Exporte as variáveis no `.env` para habilitar tracing no agente LangGraph:

```env
LANGFUSE_PUBLIC_KEY="..."
LANGFUSE_SECRET_KEY="..."
LANGFUSE_HOST="http://localhost:3000"
LANGFUSE_USER_ID="fackel"  # opcional
```

O tracing é opcional: se as chaves não estiverem definidas, o agente roda normalmente.

## ⚡ Usage

### Passive Intelligence Only (Default)

```bash
uv run fackel example.com
```

### Passive + Active Scan (Authorized Targets Only)

```bash
uv run fackel example.com --active-scan
```

### Saídas Estruturadas

- O agente gera relatório em Markdown/HTML (opção `--output`).
- Sempre é salvo um JSON estruturado com hosts, serviços, CVEs e evidências para correlação posterior (mesmo nome do HTML, com extensão `.json`, ou `<dominio>_report.json`).

### Streaming API (Server Mode)

Start the FastAPI server for real-time analysis streaming:

```bash
uv run fackel serve --host 0.0.0.0 --port 8000
```

The API exposes a streaming endpoint that emits Server-Sent Events (SSE) with incremental analysis progress:

**Endpoint**: `POST /api/analyze/stream`

**Event Types**:
- `step_update` — Tool execution progress
- `partial_report` — Incremental analysis after each tool
- `policy_decision` — Adaptive tool selection events
- `final_report` — Complete intelligence report

For detailed streaming integration, see [docs/vector_store_playbooks.md](docs/vector_store_playbooks.md).
